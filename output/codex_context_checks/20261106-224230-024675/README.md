# Codex 현재 모델의 전체 코퍼스 수용 검사

결론: **자료88건 전체가 동일 CLI 세션의 기본 유효 컨텍스트 안에 들어갔다. 서비스 컨텍스트 초과 조건 미충족.** 이 검사는 입력 전달/수용 여부 검사이며 내용 기억·연구 품질 검사나 고립된 본문의 정확한 토크나이저 합계 증명이 아니다.

| 같은 세션의 순차 입력 | 새로 전달한 문서 | 그 요청의 입력 토큰 | 세션 누적 입력 토큰 |
|---|---:|---:|---:|
|1|82|149156|149156|
|2|4|271278|420434|
|3|2|344989|765423|

총88건/1428935자 본문을 문서 경계로3회에 나누어 같은 정확한 세션ID에 재개했다. 매번 받은 JSON은 received=true다. 실행 기록의 token_count.info.last_token_usage.input_tokens와 total_token_usage.input_tokens를 구분했고, 마지막 요청은344989토큰/유효한도475000이었다. 저장된 해당 세션에서 압축 이벤트는0이었다. 세 요청 누적765423은 한 요청의 컨텍스트 크기가 아니다. CLI 기본 표시500000의95%가 실행 기록의 유효한도475000과 일치한다.

처음 한 메시지로 전송한 검사는 max1048576자/actual1457261자라는 글자 수 제한에서 중단됐다. 이것은 모델의 토큰 한도 초과 증명이 아니다. 통상적인 codex exec resume로 같은 대화에 순차 입력한 결과를 별도로 남겼으며 안전/승인 정책을 우회한 것이 아니다.

원문·질문 외의 자료/파일/도구를 사용하지 않았고 API키 과금 fallback은 없다. 이3회 검사는 ChatGPT 구독 사용량을 소비했다. 검사 세션은 요청별 토큰 기록 확인을 위해 일반 CLI 세션 파일로 남겼으며 다른 세션은 읽지 않았다. 프로젝트에는 해당 세션의 토큰 숫자/컨텍스트/압축 여부만 복사했다.

## 기록

- [최종 검사 상태](run.json)
- [첫 집계 방식 보존](run-initial.json): exec resume의 누적 사용량을 요청 크기로 해석한 초기 inconclusive 상태. 실제 세션의 마지막 요청 사용량을 확인해 사후 정정했다. 정정에 새 외부 요청을 사용하지 않았다.
- [토큰 집계 원본 필드](token-usage-evidence.json)
- 각 chunk-N/prompt.txt: 실제 전달한 자료. chunk-N/response.json/events.jsonl/transport.json도 보존했다.

이 결과로 그래프 기능 성공을 정식 과제의 컨텍스트 초과 증명으로 사용하지 않는다. 기존 Gemma/Nano의 토크나이저 측정은 해당 모델에만 유효하다. 현재 모델로 정식 비교를 하려면 의미 있는 공식 자료를 확장하고 분량/모델 자체 한도 조건을 다시 확인하거나 실험 모델/범위를 재설계해야 한다. 단순 패딩·자료 중복·인위적인 컨텍스트 축소로 조건을 통과시키지 않는다.

모델의 Codex 기본500000/API 공개최대1050000 구분은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol)를 확인했다. API 최대값을 현재 CLI 유효한도 또는 모델 내부 아키텍처 자체 한도로 단정하지 않는다.
